# 用户拿来成图时怎么复查

先读对应页 JSON、角色卡和用户确认过的线框；缺少其中一项就说明只能做哪部分检查。看不清文字时直接说看不清，不猜正确与否。把观察到的偏差与用户想改的内容分开；本插件负责复查和建议，未获修改要求不要改源页。

| 检查项 | 对照什么 | 报告方式 |
| --- | --- | --- |
| 格数和位置 | panels 数量、order、rect/quad；cut 页参考裁剪文件 | 例如“第 2、3 格中间多出一条边框”，不要笼统说布局差 |
| 阅读顺序 | RTL 从右上进入、同段向左、再向下；用户选 LTR 则反过来 | 指出从哪一格跳错到哪一格；气泡顺序也要看 |
| 人物身份 | 角色卡外观、衣服、触发词所对应的角色 | 区分身份混合、衣服变化、姿势变化；多 LoRA 吞特征只是可能原因，不能仅凭图就断定执行参数 |
| 每格的故事 | 景别、角度、画面、视线和动作方向 | 按 order 标注，例如“第 3 格应为背面，成图仍是正脸” |
| 左右关系 | 人物原有站位、视线、镜头换侧 | 检查人物是否突然换边，是否需要补环境格交代位置 |
| 台词 | 逐字对照 texts[].text（兼容旧 dialogue[].text），检查中文错字、漏字、标点和说话者 | 引用明确可辨认的错字，不擅自替换用户原台词 |
| 多余文字 | 无对白页应无气泡；其他页只应有明确给定的文字 | 标出乱码日文气泡、可见 id、镜头标签、重复旁白 |
| 斜切和出格 | cut 是否已实际裁剪；moss overlay 的跨格人物是否正确，layer 的图片是否已生成叠加 | 没做的步骤写“待处理”，不要因为源 JSON 有该字段就当成图已实现 |

结果先说最影响故事的一到三个问题，再列需处理的格子。建议分清：源分镜改法、重画某格、只修文字、按 quad 裁剪、后续叠图。多人换人和修细节的重画强度不同，详见 MOSS 要点；CLI 支持生成、重画、拼页和排字；只有用户同意后才执行，每次先说明张数、按实际尺寸和步数估算的耗时，局部重绘先展示 --mask-only 的遮罩预览。

如果用户只要复查，交付清单就停。用户明确要改分镜时才改指定字段，重新 validate 和 preview，并回到整页确认步骤；不能把一次成图复查当作自动重写剧情或自动启动生成的授权。

草稿复查：青色格子/人物、红色跨格人物/标题、绿色文字框；figures 姿势、朝向、左右站位和景别对应；文字按方向写出原文，不被边界裁掉。竖排框明显扁宽时处理 warning。生产 JSON 的 text 条目都有 text 字段，size_check 只在 CLI 报告/map。
