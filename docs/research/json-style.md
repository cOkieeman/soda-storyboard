# JSON 写法对出图质量的影响（2026-10-21）

## 起因

用插件（P2）生成的两页（彩虹、布丁）出图后，用户发现人物变形、文字问题多；而用户手上的一份范例 JSON（2 格 + 主角大图 + 大量竖排旁白，配一张线框分镜稿）出图效果很好、字很准。

## 对照过程（均为无 LoRA、种子 302，图在 `output\MOSS\plugin-test\`）

1. 25 / 30 / 50 步、v2 质量档（`nolora_25-30-50_对比.jpg`）：用户未特别指出步数差异。
2. 底模 × 文字条目格式（`textfield_底模对比.jpg`）：台词放进独立 `text` 字段。
3. **Claude 按范例写法手写同一页**（`example_style_base_s302`、`example_style_sft_s302`；JSON 和线框在 `docs/tasks/refs/example-style/`）。

## 结论（用户看图）

- 第 3 组**无论 Base 还是 SFT 都明显更好**。问题出在 JSON 写法，不在模型或步数。
- SFT 这张出现了手部反关节，属于小问题；Base 这张没有。两个底模都可用。

## 范例写法的要点（编译器要学的）

1. 文字条目：`text` 字段放原文，`caption` 只写样式和位置。
2. 竖排文字框是细长竖条，按字数和列数量尺寸；长句用 `\n` 换成多列。插件版那句台词的框是扁框（宽 261、高 102），竖排字必乱。
3. 有主角大图（`label: "character"`），框横跨页面中段、压在格子上面，自然形成出格。
4. 有旁白框、拟声词、标题，每个都有自己的位置。
5. summary 是一整段英文画风描述（上色、笔触、色调、光线、文字要求、人物和场景标签）。
6. 每格 caption 是具体的英文描述，人物的年龄、发型、五官、服装每次都写全。
7. 作者先画线框分镜稿（青框格子、红框主角、绿框文字），再照着写 JSON。
