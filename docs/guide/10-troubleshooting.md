# 10. 常见问题与已知限制

画面有问题时，可以从草稿、提示词和成图逐步排查。位置在草稿里就不对，需要回编辑器调整；最终提示词写错了，检查角色卡或译文；提示词已经正确，成图仍有偏差，再考虑换种子、提高质量或修局部。

![本地草稿与彩色成图](images/stretch-color-process.jpg)

图：「起身舒展」的草稿与成图。主格落实了全身舒展的重点，第二格仍偏坐姿，和“推开椅子站起”的描述有偏差。检查草稿与最终提示词后，还需要逐格看实际成图。

## 画面问题

| 问题 | 先试什么 | 需要知道的限制 |
| --- | --- | --- |
| 两个人穿成同一套衣服 | 在各自角色卡里写清服装款式和颜色，核对中英文是否一致 | 模型仍可能串衣服，角色描述越含糊越难区分 |
| 想同时挂两个人物 LoRA | 选一个主要角色 LoRA，其余靠外观；或整页不用 LoRA | 当前整页流程最多一个人物 LoRA，不安排逐个换人 |
| 格子里的人很小，脸或手崩了 | 减少格数、放大关键人物，或试用 final、单格 detail | 放大采样后仍可能有细节问题，需要检查结果 |
| 关节摆好了，成图动作仍不对 | 核对姿势预设、关节和文字描述是否一致，复杂动作要写清可见范围 | 关节会近似转成文字，无法提供精确的骨架控制 |
| 斜切边不干净 | 先检查 quad 和留白，用默认 cut 编译后 compose | MOSS 按矩形安排内容，后裁斜边可能切到人物；实测质量有限 |
| 台词错字、长句挤在一起 | 适当缩短可以精简的句子，或改用 lettering 后排字 | 默认在超过 20 字时提醒，短句也需要人工校对 |
| 中文编辑后英文没变 | 查看过期、缺失或 legacy 状态，重新 todo / apply | 编译时不会调用翻译服务，没有新鲜译文时会退回中文 |
| 改了衣服，译文状态没过期 | 看重新编译后的最终提示词 | 这是预期行为：角色外观由程序读取，不进入场景译文哈希 |

`--outfit` 或角色卡的 `clothing` 写成中文时，当前代码可能把中文原样拼进英文 caption。外观描述可以分别填入 `appearance.zh` 和 `appearance.en`；如果希望最终提示词是纯英文，服装列表也需要用英文填写，并在编译后核对。

## 命令、编辑器和保存

| 现象 | 处理 |
| --- | --- |
| 安装后找不到命令 | 执行 `uv tool update-shell` 后重开终端，或用安装器给出的可执行文件路径；也要确认包安装在当前使用的环境中 |
| 编辑器打不开 | 用 `edit --detach --no-browser --json` 获取实际 URL；确认后台服务已启动，浏览器能访问本机回环地址 |
| 8780 被占用 | edit 会尝试其他空闲端口，使用返回的 URL 打开编辑器，旧书签可能仍指向原端口 |
| 网页里刚改的内容被 AI 改回去 | 网页保存完成后，让 AI 重新读取页文件，再继续修改，避免沿用缓存版本 |
| 出现保存冲突 | 暂停双方写入，按冲突提示选保留版本，保存后再继续 |
| 停服务时身份不匹配 | 核对项目和启动实例；旧状态文件中的 PID 可能已经被其他进程使用 |
| 旧页提示“需要重新翻译”，标签却不清楚 | 以详细提醒和 `translate --todo` 为准，按新版场景规则重译 |
| 颜色提取后保存模板报错 | 当前实测 `--mode color --save` 可能触发 `KeyError: normalized`；可只提取并预览，由插件核对坐标后保存页，重复执行同一保存命令仍可能报错 |

## ComfyUI、模型和字体

```powershell
soda-storyboard comfy check --project my-project --json
```

| 现象 | 处理 |
| --- | --- |
| 连不上 ComfyUI | 确认服务已启动，核对配置的协议、地址和端口；默认 8190，使用时以实际端口为准 |
| 缺节点或模型 | 按 check 的具体名单补齐，模型名按 ComfyUI 下拉中的相对文件名填写；节点检查“无法确认”时到界面核对 |
| 导入节点能看图，采样报错 | 预览和采样需要的节点不同，需要检查 MOSS 支持、编码器、VAE 和工作流 Loader 是否齐备 |
| 便携版说缺核心库 | 用 `python_embeded/python.exe` 安装 wheel，并重启 ComfyUI；系统 Python 的安装不能代替它 |
| 找不到 `uv_build` | 检查是否从 Git 源码安装，便携版改用预构建 wheel |
| 超时了，不知道是否还在生成 | 根据任务号查看 ComfyUI 队列，确认原任务状态后再决定是否重新提交 |
| 排字缺字或找不到字体 | 用 `letter --font <字体文件>` 指定有中文字形的字体，再核对成图 |
| 换底图后导出提示派生结果失效 | 对当前底图重新 compose / letter，再导出 |

生成失败时，终端会给出简短原因，需要更多信息时可以查看故事项目 `logs/` 中的诊断。向别人求助时，错误摘要、版本和必要参数通常更方便排查；分享日志前，记得检查其中的本机文件信息。

`validate` 检查的是结构和部分规则。没有 error 后，还需要查看 warning 的具体原因；info 中的本页 LoRA 则是说明信息。角色、手、斜格和台词最终画得怎样，需要在成图后检查。
